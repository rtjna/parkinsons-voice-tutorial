# Can a voice model work for a new patient?

A short healthcare ML tutorial using the public UCI Parkinsons Telemonitoring dataset. The aim is to estimate **motor UPDRS severity**, not diagnose Parkinson's disease or forecast progression.

The main lesson is how repeated recordings can make an evaluation look better when the same patients appear in training and testing.

## Run locally

Use Python 3.12 and run these commands from the project folder:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python SLT.py
```

On Windows, activate with `.venv\Scripts\activate`. The code runs on a CPU. The public data table is included, so the analysis runs offline after dependencies are installed. If the data file is absent, the script downloads it from UCI.

For Colab, download `SLT.ipynb` from this repository. Open [Google Colab](https://colab.research.google.com), choose **File > Upload notebook**, and select **Run all**. It contains the same analysis, with explanations between cells. Colab downloads the public data if it is not already present.

## What the analysis does

1. Checks the 5,875-row table and selects the 16 voice measures.
2. Reserves nine patients for testing; the other 33 form the development set.
3. Compares a training-mean baseline, ridge regression, and a random forest using five-fold validation grouped by patient.
4. Selects the smallest **mean patient MAE**: calculate each patient's mean absolute error, then average patients equally.
5. Evaluates the selected model on the nine held-out patients and calculates a rough patient-bootstrap interval.
6. Adds a fixed-forest diagnostic comparing patient and recording splits. It does not change model selection or tune settings.

The ridge scaler is fitted inside each training fold. Patient ID is used only for grouping. Both clinical scores, age, sex and recording time are excluded from predictors to keep the primary question about voice alone.

## Results from the supplied run

Seed: 42. Development: 4,640 recordings from 33 patients. Test: 1,235 recordings from nine patients. No patient crosses that boundary.

| Development comparison | Mean patient MAE (UPDRS points) |
| --- | ---: |
| Mean baseline | 7.10 |
| Ridge | 7.52 |
| Random forest | 7.65 |

The **mean baseline** is selected. Its test patient MAE is **6.90** points, with a rough bootstrap 95% interval of **4.99–8.82**. The fixed forest's test MAE is **6.77**, but that diagnostic does not replace the validation-based selection. A small difference on nine test patients is not evidence of a reliable advantage.

The same forest settings give **5.21** patient MAE with a random recording split, where all 42 patient identities occur on both sides. This answers a different question. The test sets differ, so the gap is not a controlled estimate of how much bias patient overlap causes.

The model settings and split were kept fixed after evaluating the test patients. These configurations do not improve on the baseline in grouped development validation; this does not establish that all voice models would fail.

## Limits of this exercise

There are 42 people with early-stage Parkinson's disease and no healthy control group. Repeated recordings do not create thousands of independent patients. Motor UPDRS targets are **linearly interpolated**, rather than freshly assessed for every recording. The nine-patient bootstrap interval is approximate and conditional on this fitted model. No clinical threshold for acceptable error was established.

## Development-only extension

Run this after the original experiment:

```bash
python SLT.py --development-only
```

This compares voice alone with voice plus age and sex on the same 33 development patients and the same five grouped folds. It writes the six model/feature-set scores to `results_extension/development_comparison.csv`, with details in `results_extension/metrics.json`. The extension function receives only development rows and returns before any test evaluation. The original `results/` files stay unchanged. The notebook also has a separate cell for this exercise.

Look at each model's change in patient MAE. Adding demographics changes the question: the inputs now include age and sex as well as voice. Keep the original test results as the original experiment; do not repeatedly select changes using those nine patients. A new confirmatory experiment needs a test group reserved before new choices, preferably external data.
